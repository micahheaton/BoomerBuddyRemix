# Owner Command Center

## Questions before cards

The command center should answer: Is the product protecting people safely? Are households activating and retaining? Is fraud quality stable? Is revenue healthy and reconciled? Which operational queue needs attention? Which provider or cost is deteriorating?

## First scorecard

1. **Safety:** evaluation pass rate, false-negative alerts, high-risk checks, review backlog.
2. **Activation:** paid/eligible households, protected members, orientation and practice completion.
3. **Revenue:** MRR framework, plan mix, churn, failed payments, partner pipeline; seeded in Run 1.
4. **Unit economics:** provider cost per check, messaging cost, contribution-margin framework.
5. **Operations:** open support/escalation state, stale opportunities, failed jobs, provider health.

Every metric links to a definition and underlying filtered records. “Up 12%” is forbidden unless the comparison period, denominator, source, and completeness are known.

## Owner assistant boundary

A future assistant may query read models, explain metric changes, and draft investigations. It cannot issue refunds, contact customers, change employee access, alter forecasts, initiate payments, or delete records without an authorized human workflow and audit event.

## Build Run 1

Implement a responsive HQ shell with clearly labeled seeded cards and drill-down tables. Demonstrate shared domain models, authorization, provider health, and audit visibility; do not confuse a dashboard mock with an operating company.
