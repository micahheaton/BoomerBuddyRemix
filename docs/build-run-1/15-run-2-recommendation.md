# Run 2 Recommendation

Recommendation: **authorize a bounded evidence-and-production-foundation run only after the founder resolves its decision inputs; do not begin a public beta, accept payment, or broaden artifact types.** Build Run 1 is a local PASS, not launch approval.

## Run 2 objective

Prove that the core pause/check/connect workflow and independent family consent can work with real identity, real devices, representative evaluation, and production-like operations. The run should reduce the first five risks—false negatives, family abuse, weak paid demand, commodity classification, and sensitive-data exposure—before adding images, documents, audio, recovery casework, or growth automation.

## Ordered workstreams

1. **Consent and identity.** Implement managed customer/employee identity in staging, MFA/step-up/recovery, and a complete identity-bound protected enrollment and withdrawal API/UI. Convert consent to versioned append-only evidence and exercise coercion, expiry, revocation, allowance lapse, and support boundaries.
2. **User and outcome evidence.** Run moderated older-adult and adult-child task studies across accessibility needs. Define verified safe-action completion without treating a click as proof; instrument consent, provenance, denominators, late events, and retractions before HQ reports an outcome.
3. **Fraud-quality evidence.** Acquire or license a representative set, use two independent reviewers plus adjudication, seal the evaluation split, declare action-safety/false-negative/false-positive/calibration thresholds, and compare the first reputation provider under outage and rollback tests. Keep URL fetching prohibited.
4. **Production-like foundation.** Qualify managed PostgreSQL, managed KMS/rotation, durable outbox and retention workers, idempotent mutations, invitation-expiry cleanup, complete export/erasure, observability, rate/abuse controls, restore, incident, and dependency-remediation paths in staging.
5. **Native proof.** Build and device-test iOS and Android intake, secure session/household state, error/offline paths, deletion, and VoiceOver/TalkBack. Limit native scope to the existing text/URL workflow and platform sharing boundary.
6. **Commercial discovery, not premature integration.** Test the Free/Plus/Family propositions and direct-family buying process while conducting narrow credit-union discovery. Prepare provider-neutral commerce adapters, but do not charge, purchase broad tooling, or build partner-specific features without evidence and the first-dollar gate.

## Exit gate

Run 2 should pass only when dated evidence shows:

- no unresolved Critical/High application or external security finding;
- identity-bound consent and cross-household/device authorization regressions pass;
- managed database/KMS, durable jobs, restore, deletion/export, observability, and incident exercises pass in staging;
- native critical journeys pass on supported iOS and Android devices with manual accessibility coverage;
- the adjudicated fraud set meets founder-approved thresholds with zero forbidden-action regressions and explicit provider-failure behavior;
- observed users can complete Check and Family tasks, and outcome instrumentation never overclaims protection or loss prevention; and
- legal/privacy/accessibility/security owners sign the relevant [Launch Definition of Done](../gauntlet-zero/40-launch-definition-of-done.md) evidence. Payment remains a separate first-dollar decision.

## Founder decisions before authorization

Choose the primary Run 2 learning motion (direct family versus a narrowly bounded sponsor discovery track), the research budget, acceptable evaluation thresholds, supported device matrix, identity/KMS/database procurement envelope, and whether the working brand/pricing hypotheses are ready for controlled testing. The current recommended defaults and tradeoffs are in [Founder Decisions](../gauntlet-zero/42-founder-decisions.md).

Run 2 must not start by silently assuming vendor, pricing, legal, or distribution answers. The implementation sequence remains consistent with the [Implementation Roadmap](../gauntlet-zero/41-implementation-roadmap.md).
