# Reviewer Disagreements and Resolutions

## Family network as moat vs direct competitive parity

- **Position A:** a scanner connected to family members is inherently differentiated.
- **Position B:** Trend Micro ScamCheck already offers multi-artifact checking and a six-person Family Circle with shared alerts.
- **Resolution:** B. Family is necessary packaging, not a moat by itself. Test differentiation in consent design, safe-action completion, recovery follow-through, measured older-adult usability, reproducible safety quality, and distribution.

## Household graph as network effect vs activation loop

- **Position A:** more families automatically create a defensible network effect.
- **Position B:** privacy boundaries mean one household does not improve another household’s immediate product value; invitations and referrals may only lower activation or acquisition friction.
- **Resolution:** B. No true network effect is demonstrated. Measure within-household collaboration, referral conversion, and acquisition cost separately; never weaken consent or pool customer artifacts to manufacture cross-household value.

## LLM as product core vs adjunct

- **Position A:** model reasoning is the differentiating detector.
- **Position B:** models are untrusted synthesis components inside an evidence pipeline.
- **Resolution:** B. Build Run 1 uses deterministic signals and a provider port; any model must pass the same evaluation, return structured evidence, and never override authoritative indicators silently.

## One web application vs separate customer and HQ applications

- **A:** one app reduces early burden.
- **B:** separate apps reduce accidental employee/customer boundary mixing.
- **Resolution:** separate deployable web and HQ apps over one modular API, sharing tokens/contracts but not routes or sessions by assumption.

## Store artifacts vs analyze ephemerally

- **A:** history and model improvement require retention.
- **B:** sensitive content creates disproportionate breach and trust risk.
- **Resolution:** private-by-default, short configurable retention, encrypted sensitive fields, redacted history, deletion, and evaluation datasets separated from user data. Never train from submissions by default.

## B2C-first vs B2B2C-first

- **A:** direct users create learning and brand.
- **B:** partners offer distribution and credibility.
- **Resolution:** parallel discovery, sequential product proof. Validate family activation directly while designing sponsor entitlements; avoid enterprise customization before evidence.

## Retrievable vs non-retrievable safe word

- **A:** retrieval is convenient during an emergency.
- **B:** a central readable secret is a breach and account-takeover liability.
- **Resolution:** non-retrievable verifier, replace-on-recovery, rate-limited verification, explicit limitations.

## Microservices vs modular monolith

- **Resolution:** modular monolith with transactional outbox. Current team size and domain uncertainty do not justify distributed operations; module ports preserve later extraction.
