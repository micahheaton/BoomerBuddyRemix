# First Cohort and Discovery Workflow

Status: **prepared locally; no participants, enrichment, outreach, or production evidence**

## Boundary

The first product cohort expands only through the current 1 -> 3 -> 5 evidence gates. Each expansion
requires the prior cohort gate to pass; this is a cap, not an acquisition target. Names,
addresses, phone numbers, emails, relationship details, interview notes, and consent evidence never
belong in Git. This document is a blank operating template, not a lead list and not authorization to
contact anyone.

No address-book import, contact scraping, purchased list, Apollo enrichment, automatic email/SMS,
or transferred consent is permitted. Research participation is distinct from marketing, sales,
referral, testimonial, media, and product-service consent.

## Founder-held cohort worksheet

Keep the worksheet in an approved company-controlled system with least-privilege access. Use an
opaque candidate code in engineering evidence.

| Field | Allowed value |
| --- | --- |
| Candidate code | random opaque code; no initials or contact data |
| Perspective | older adult / caregiver / paired family / accessibility / professional / institution |
| Recruitment source | direct founder relationship / consented referral / approved partner |
| Contact authority | not_requested / recipient_initiated / explicit_research_consent |
| Research consent | pending / granted / withdrawn / expired |
| Product consent | separate pending/granted/withdrawn record |
| Accessibility needs | participant-chosen accommodation category; no diagnosis in product logs |
| Session state | invited / scheduled / completed / declined / withdrawn |
| Evidence tier | pending_human until a consented session actually occurs |

The founder or assigned research owner must record the approved recruitment copy, consent version,
purpose, expiry, withdrawal path, retention decision, and whether any follow-up is separately
authorized. Declining research cannot affect product access.

## Discovery rehearsal

Before any real invitation:

1. rehearse with synthetic records only;
2. verify the invitation contains no pricing promise, diagnostic claim, urgency pressure, or implied
   institutional endorsement;
3. verify the participant can decline or withdraw without losing service;
4. verify notes and recordings remain disabled unless separately consented and approved;
5. verify the researcher can report themes without copying submitted Check or Feedback content;
6. route product findings to a bounded internal queue with no participant destination or raw note;
7. close the synthetic record and test the retention/withdrawal plan.

## B2B segmentation rehearsal

The NCUA import and opportunity model are official-snapshot segmentation tools, not proof of buyer
intent. A rehearsal may filter synthetic or approved public institution metadata, explain each fit
factor, create a draft, and leave the opportunity unsent. Real enrichment and outreach remain off.

## Exit criteria

This workflow remains `prepared` until a human/privacy review approves the worksheet system,
recruitment language, consent, retention, accessibility accommodations, and named accountable owner.
No Run 3 evidence claims a participant, interview, conversion, lead, or outreach event.
